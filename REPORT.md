# Лабораторная работа №1

## Тема

Абстрактные структуры данных.

## Индивидуальный вариант

Вариант 4 — Full Binary Tree.

## Описание структур

### Массив

Массив хранит элементы в непрерывной области памяти. Доступ к элементу выполняется по индексу. При заполнении выделенной памяти вместимость увеличивается в два раза.

Преимущества: быстрый доступ по индексу, простая организация, хорошая локальность данных.

Недостатки: вставка и удаление в середине требуют сдвига элементов; увеличение массива требует копирования.

Применение: хранение таблиц значений, последовательностей, буферов и наборов однотипных данных.

### Односвязный список

Каждый узел содержит значение и указатель на следующий узел.

Преимущества: размер изменяется динамически; вставка после известного узла не требует сдвига элементов.

Недостатки: переход возможен только вперёд; поиск и доступ по позиции требуют последовательного просмотра.

Применение: реализации стеков, простых очередей и последовательностей с частыми вставками и удалениями.

### Двусвязный список

Каждый узел содержит значение, указатель на следующий и указатель на предыдущий узел.

Преимущества: перемещение в обе стороны; вставка и удаление известного узла выполняются за постоянное время.

Недостатки: дополнительные затраты памяти на второй указатель; поиск узла занимает линейное время.

Применение: списки переходов вперёд и назад, очереди с удалением с обоих концов, списки задач.

### Стек

Стек работает по принципу LIFO: последним добавлен — первым извлечён.

Преимущества: простые операции добавления и извлечения; обе операции выполняются за O(1).

Недостатки: доступен только верхний элемент; произвольный поиск не является основной операцией стека.

Применение: вызовы функций, отмена действий, проверка скобочных выражений, обход графов и деревьев.

### Очередь

Очередь работает по принципу FIFO: первым добавлен — первым извлечён.

Преимущества: добавление в хвост и извлечение из головы выполняются за O(1) при хранении указателей на голову и хвост.

Недостатки: доступ к произвольному элементу требует просмотра очереди.

Применение: очереди задач, обработка запросов, буферизация и обход в ширину.

### Full Binary Tree

В работе используется бинарное дерево поиска. Для каждого узла значения меньше ключа размещаются слева, большие и равные — справа. Повторяющиеся значения разрешены.

Full Binary Tree — бинарное дерево, в котором каждый узел имеет либо ноль, либо двух потомков. Узлы с одним потомком не допускаются.

Преимущества: простая проверка свойства; удобное рекурсивное представление; обходы позволяют получить разные порядки элементов.

Недостатки: обычное дерево поиска не поддерживает автоматическую балансировку; высота может достигать количества узлов; вставка может нарушить свойство Full, поэтому предусмотрена отдельная проверка.

Применение: представление полных бинарных структур, некоторых деревьев выражений и турнирных схем.

## Оценка сложности

Обозначения: n — число элементов, h — высота дерева.

| Структура и операция | Сложность |
|---|---:|
| Массив: доступ по индексу | O(1) |
| Массив: добавление в конец | O(1) амортизированно, O(n) при расширении |
| Массив: вставка и удаление по индексу | O(n) |
| Массив: поиск значения | O(n) |
| Односвязный список: добавление в голову | O(1) |
| Односвязный список: добавление в хвост | O(n) |
| Односвязный список: поиск | O(n) |
| Односвязный список: вставка после известного узла | O(1) |
| Односвязный список: вставка перед узлом | O(n) |
| Односвязный список: удаление головы | O(1) |
| Односвязный список: удаление хвоста или по значению | O(n) |
| Двусвязный список: добавление/удаление головы и хвоста | O(1) |
| Двусвязный список: поиск | O(n) |
| Двусвязный список: вставка/удаление известного узла | O(1) |
| Стек: push, pop | O(1) |
| Стек: вывод | O(n) |
| Очередь: push, pop | O(1) |
| Очередь: вывод | O(n) |
| BST: поиск и вставка | O(h), худший случай O(n) |
| BST: обход | O(n) |
| Проверка Full Binary Tree | O(n) |

Для сбалансированного дерева поиска h имеет порядок log n. В реализованном обычном BST балансировка не выполняется, поэтому гарантии O(log n) нет.

## Проверка дерева

Для каждого узла проверяется наличие потомков:

- оба указателя пусты — лист, условие выполнено;
- оба указателя заполнены — проверяются оба поддерева;
- заполнен только один указатель — дерево не является Full Binary Tree.

Пустое дерево и дерево из одного узла считаются Full Binary Tree.

## Контрольные примеры

| Проверка | Ожидаемый результат |
|---|---|
| Проверка пустого дерева | TRUE |
| Проверка дерева из одного узла | TRUE |
| Дерево из значений 8, 4, 12, 2, 6, 10, 14 | TRUE |
| Вставка одного потомка в листовой уровень | FALSE |
| Поиск существующего значения | TRUE |
| Поиск отсутствующего значения | FALSE |
| Извлечение из пустого стека | Сообщение о пустом стеке |
| Извлечение из пустой очереди | Сообщение о пустой очереди |
| Запуск второй версии с тем же JSON-файлом | Данные общих структур сохраняются |

## Визуальные примеры

Full Binary Tree:

```text
        8
       / \
      4   12
     / \  / \
    2  6 10 14
```

В этом дереве у каждого внутреннего узла два потомка, поэтому проверка возвращает TRUE.

Дерево, которое не является Full Binary Tree:

```text
        8
       / \
      4   12
     / \  / \
    2  6 10 14
          /
         8
```

У узла со значением 10 только один потомок, поэтому проверка возвращает FALSE.
